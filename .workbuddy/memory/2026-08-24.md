## 【修正】UiTheme 全局挂载无效（Root.Theme 不穿透 CanvasLayer）
- 现象：用户实跑后 UI「还是原来的，除了标题印章什么都没变」——整片主题（面板/按钮/文字色）都没生效。
- 根因（关键坑）：`GetTree().Root.Theme = ...` 在 Godot 4 下**不会可靠传播到 CanvasLayer 内部的 Control**（Hud/GameMenu/LoadingScreen 均直接继承 CanvasLayer）。红印章之所以显示，是因为它用 `AddThemeStyleboxOverride` 直写，不依赖主题传播——这掩盖了问题。
- 修复：在 `UiTheme.cs` 新增 `Apply(Node root)` 递归把 `Theme` 挂到子树每个 Control（绕开传播限制）；在 `Hud/_Ready`、`GameMenu/_Ready`、`LoadingScreen/_Ready` 末尾各自调用 `UiTheme.Apply(this)`。`Main` 里的 `Root.Theme` 保留作兜底（对直接挂在 Root 下的 Control 仍有效）。
- 经验：Godot 4 凡 UI 用 CanvasLayer 承载，全局主题务必在每个 CanvasLayer 子树内显式挂载，不能只靠根 Window 主题。
- 验证：`dotnet build -p:UseSharedCompilation=false` 0 警告 0 错误。

## 【修正】文字模糊 + 悬浮菜单白字看不清
- 现象①：窗体放大后文字全糊（高分屏尤甚）。根因：`project.godot` 未开 `allow_hidpi`，Godot 按逻辑分辨率渲染、系统放大窗口 → 越放越糊；且 `UiTheme` 字体 `Oversampling` 写死 1.0 加剧发虚。
- 修法①：`project.godot` 的 `[display]` 加 `window/handling/allow_hidpi=true`（按设备物理像素渲染）；`UiTheme` 字体 `Oversampling` 1.0→1.5（缩放更清晰）。
- 现象②：鼠标悬浮下拉菜单文字变白、看不清。根因：`UiTheme` 把 `PopupMenu` 的 `font_hover_color` 设成纯白（白字落浅色面板不可见）。
- 修法②：`PopupMenu` 悬停 `font_hover_color` 改 `Ink`（墨字），悬停 stylebox 改 `CeladonL`（浅青底）；`ItemList` 的 `selected_focus` 也改 `CeladonL`（浅青底+墨字，高对比）。
- 验证：`dotnet build` 0 警告 0 错误。
- 注：`stretch/mode=canvas_items`+`aspect=expand` 本身不缩放模糊，无需动。

## 【修正】悬浮菜单白字仍出现（OptionButton 弹出层漏主题）
- 现象：上面改了 `PopupMenu.font_hover_color=Ink` 后，用户实跑「悬浮菜单文字还是白色」。
- 根因（关键坑）：白字来自所有下拉 `OptionButton`（设置·分辨率/自动保存、TopBar·速率、PolicyPanel·等级）——其弹出层 `PopupMenu` 在**运行时才生成**，且**不保证继承父节点主题**。`UiTheme.Apply(this)` 只在 `_Ready` 遍历「已存在」节点，延迟创建的弹出层被漏掉，回退 Godot 默认皮肤（蓝底+白字）。
- 修法：在 `UiTheme.cs` 新增 `StyleOptionPopup(OptionButton opt)`，直接 `opt.GetPopup().Theme = Build()` 钉死；在每个 `OptionButton` 创建处调用（GameMenu 两处、TopBar 一处、PolicyPanel 的 `MakeLevelOption` 一处，共覆盖 5 个下拉）。
- 经验：Godot 4 凡 `OptionButton`/`MenuButton` 的下拉，须显式给其 PopupMenu 设主题，不能指望继承或 `_Ready` 遍历。
- 验证：`dotnet build` 0 警告 0 错误。
