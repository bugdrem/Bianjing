## 接入开源 3D 树木模型到地图
- 需求：寻找开源 3D 树木模型并加载到地图（替代现有程序化原始体树）。
- 资产：**Kenney「Nature Kit」CC0 1.0**（公共领域，可商用无需署名），用户已下载到本地
  `E:\迅雷下载\kenney_nature-kit.zip`；包内 60 个树木 .glb（每个 5–32 KB，共 329 个模型）。
- 选型落地 `assets/trees/`：
  - 阔叶 `tree_default.glb`、针叶松 `tree_pineDefaultA.glb`、果树 `tree_plateau.glb`
  - 授权留档 `assets/kenney_License.txt`
- 关键验证（写码前先查清资产结构，避免白模）：这批 GLB **无贴图**（images/textures=0、
  baseColorTexture=no），颜色来自材质 baseColorFactor；每个 GLB = 1 mesh / 2 primitive
  （树冠+树干各一材质），**无顶点色**——正好命中"无顶点色时回退材质色烘顶点色"的合并管线。
- 实现（3 文件，零回归设计）：
  - 新增 `scripts/configs/TreeModelConfig.cs`：树种路径/高度/去饱和参数（RULES：常量进 configs）。
  - 新增 `scripts/render/TreeModelFactory.cs`：遍历 GLB 的 MeshInstance3D，按节点变换把多子网格
    合并为单一 ArrayMesh，材质色烘进顶点色，归一化到"底面 y=0、高 1、水平居中"，按树种缓存；
    复用 `BuildingAssetLoader.LoadScene` 的缓存。失败返回 null → 回退原始体。
  - 改 `scripts/map/GridRenderer.cs`：保留原 3 个原始体层不动，**新增**每树种一个模型层
    （未配置树种的层为 null，不建层不绘制）；`CollectTree` 判定树种，有模型则整株一次成型
    （等比缩放 + 随机绕 Y 转向 + 实例色微亮扰动），否则完全走原有原始体逻辑。
- 为什么必须合并：Godot `MultiMesh` 一次只能承载一个 Mesh，而树木模型通常多子网格。
- 美术调和：Kenney 原色高饱和（树冠青绿 0.16/0.79/0.67），与本作淡雅调不搭；改为在烘焙阶段
  统一去饱和 45% + 亮度 ×0.95（保留树冠/树干固有色关系），而非用实例色通道乘算。
- 编译：`dotnet build -p:UseSharedCompilation=false` 0 警告 0 错误。
- 待用户实跑：首次用 Godot 编辑器打开项目会自动导入 .glb（生成 .import）；
  树高/去饱和参数为 [PLACEHOLDER]，需实跑按观感微调。

## 树木资产不生效的排查与修复
- 现象：接入后游戏里树仍是代码绘制的原始体。
- 根因：`assets/trees/` 下**没有 .import 文件**（Godot 从未导入这 3 个 .glb），
  `ResourceLoader.Load<PackedScene>` 返回 null → 走原始体回退。放资产后必须让编辑器导入一次才生成 .import。
- 修复：`TreeModelFactory` 装载改为**两条路径**——① 已导入 → PackedScene 缓存（导出后可靠路径）；
  ② 未导入 → 用引擎自带 `GltfDocument` 运行时从文件解析（res:// 优先，失败再退回
  `ProjectSettings.GlobalizePath` 本地绝对路径），**免于"必须先开一次编辑器"**。
- API 坑（已写入 MEMORY.md）：Godot 4.7 的 C# 绑定把缩写改成了 PascalCase ——
  `GltfDocument` / `GltfState`（**不是** `GLTFDocument`），且 `GenerateScene()` 返回 `Node` 需转 `Node3D`。
- 注意导出：未导入的 .glb 不会进 pck，正式导出前仍应开一次编辑器生成 .import（或把 *.glb 加入导出过滤）。
- 编译 0 警告 0 错误。
