# 互市供需闭环设计（待办B 落地）

> 来源：用户「完成两个待办」——待办A=真·毛玻璃面板收尾；待办B=把 ForeignVisitor 的贸易接上城市真实供需。
> 日期：2026-08-25｜状态：代码已落地，编译 0 错 0 警告，数值待 playtest。

## Fun Hypothesis
外来访客系统好玩的核心是——**你缺什么，外城就运什么来卖；你产什么过剩，外城就高价收走**，让玩家通过城建/产业决策与四邻产生真实贸易博弈。

## Design Pillars
1. 访客行为必须读 `gs.Demand`（不是随机）。
2. 进口（补缺口·城市付钱）与出口（清积压·城市赚钱）双向闭环。
3. 玩家建田/开矿→改供需→改变访客构成（长线钩子）。

## 机制改动（已落地）
| 机制 | 改前 | 改后 |
|---|---|---|
| 访客带货 `MakeCargo` | 随机大类 1–2 种 | 城市有缺口时 70% 带**短缺货**补货，其余带邻城特产 |
| 出口收购 `SettleVenueTrade` | 随机挑第一个不短缺货买 8–24 份（仅从 venue 取） | 挑城市**最过剩**货（可撑>30天），从**贸易节点**扣库存，城市赚钱 |
| 进口售入 | 全部货强行塞入 | 仅售入**城市仍短缺**的货（已补够不强行塞，防积压） |

## 数值（全部 [PLACEHOLDER·需 playtest]，见 `VisitorConfig`）
- `ImportBias = 0.7`：城市有缺口时访客带短缺货的概率。
- `ShortageCargoMin/Max = 20/60`：短缺货单次带货量（份）。参考城市日口粮需求≈`pop×FoodPerDay`，约 1–3 天缺口量。
- `SurplusDaysThreshold = 30`：可支撑天数高于此值才视为过剩。
- `ExportMaxQty = 80`：出口单次收购上限（份）。
- `ExportStockShare = 0.5`：出口收购占过剩库存比例。

## 失败信号（playtest 前先定义"坏掉长什么样"）
- **A（进口没接需求）**：城市长期缺盐铁，但来访客从不带盐铁 → `MakeCargo` 未读 `gs.Demand.IsShort`。
- **B（进口强行塞货）**：城市某货已堆成山，来访客还不停塞同货 → 进口未检查 `IsShort` 跳过。
- **C（出口不收过剩）**：城市粮布过剩几月，外城从不清库存 → 出口未挑 `DaysOfStock` 最高项 / `IsTradeNode` 过滤把持货建筑全排除了。
- **D（误扣民居）**：居民家用库存被外城买走致断炊 → `IsTradeNode` 白名单未挡住 house 类。

## 待验证 / 已知风险
- `gs.Demand` 每日重算，访客行程期间（数秒~数十秒）快照可能过期——闭环用"到达时再查 `IsShort`"兜底，不保证绝对实时。
- 出口持货建筑若全为 null（城市无 shop/inn/workshop 时），仅进口生效、出口静默跳过（可接受）。
- 毛玻璃（待办A）的 `SCREEN_TEXTURE` 在 `CanvasLayer` 下运行时显示效果**未实跑验证**（Godot 4 已知不确定点）；若面板显示纯色/透明而非背后模糊，需改用 `BackBufferCopy` 方案。
